# 002：手把操作設計草案

狀態：DRAFT。日期：2026-10-19。完整操作設計仍待驗收，已驗的最小切片依規格 004 接入遊戲。尚未經實體手把驗收。現況以 [CONTEXT](../../CONTEXT.md) 為準；[互動配置稿](../../tools/gamepad-preview.html) 可預覽按鈕位置與輸出候選。

## 後續證據勘誤

2026-10-19 輸入切片勘誤：本文件早期「尚未接入」、「第二人按鍵待測」與「沒有實際快捷收據」已由[規格 004](004-live-input-slice.md)限定解決。固定 SF.EXE 的 DS:3EF4h／3EF5h 鍵值、DS:3F16h／3F1Eh 方向表，已在正常雙打後核對；斬的 DS:16EAh／16EBh 四招路徑及輪詢輸入已有兩人各四例。下方其餘待驗事項仍保留為完整規格的缺口，不重新阻塞已驗切片。即時入口見 [README](../../README.md)，瀏覽器合成裝置與實體裝置分開驗收。

前端 Start 暫停在可撤回切片中已實作並驗證停止核心，不送 Esc；設定面板會攔住 Start。這不表示下文所有正式選單、Select／返回配置或硬體體驗均已定版。

## 已確認的新需求

使用者於 2026-10-19 明確要求逐角色快速出招、R1 對應絕招 1，且最多四個綁定位置；有五招的角色也只綁四個。並要求規劃兩支手把雙打。此授權取代本文件較早「未授權一鍵招式」的限制，沒有授權修改原版的傷害、距離、蓄力條件或 AI。

| 快捷位置 | 預設 | 自訂 |
|---|---|---|
| R1／RB | 該角色絕招 1 | 可選該角色任一已驗招式或留空 |
| R2／RT | 該角色絕招 2 | 同上 |
| L1／LB | 該角色絕招 3 | 同上 |
| L2／LT | 該角色絕招 4 | 同上；有第五招時可替換其中一格 |

使用者最初的 LR1／LR2 依左右肩鍵語境解讀為 L1／L2。快捷編號依本專案角色設定，現階段採青衫招式順序；SP Moves 的排序與部分指令不同，差異見 [遊戲資料保存](../game-history.md)。不能將網站排列順序誤稱為原版招式 ID。

## 建議預設配置

按鈕以位置為主，避免不同品牌的字母位置造成誤解。

| 手把位置 | Xbox／PlayStation | 對戰 | 原版選單／前端介面 |
|---|---|---|---|
| 十字鍵 | 十字鍵 | 八方向 | 移動焦點 |
| 左類比搖桿 | 左搖桿 | 八方向，與十字鍵共用同一玩家 | 移動焦點 |
| 西側面鍵 | X／□ | 拳 | 不送攻擊鍵 |
| 南側面鍵 | A／× | 腳 | 確認 |
| 東側面鍵 | B／○ | 不綁定 | 前端返回；原版返回只在已驗證選單送一次 Esc |
| 北側面鍵 | Y／△ | 不綁定 | 不綁定 |
| Start | Menu／Options | 開啟前端暫停選單 | 開啟前端設定 |
| Select | View／Share | 開啟操作說明並暫停 | 開啟操作說明 |
| R1、R2、L1、L2 | RB、RT、LB、LT | 逐角色四個快速出招位置 | 選單內不觸發招式 |
| 右搖桿、搖桿按鍵 | 各品牌對應位置 | 預設不綁定 | 預設不綁定 |

手動拳腳同按由西側與南側面鍵一起按下。四個快捷位置可播放已驗證的指定招式輸入序列；不預設按住連發，也不擴充為任意跨招連段。Select 的裝置名稱只作位置提示，不接管作業系統的截圖或分享功能。

兩名玩家各自選擇裝置。第一人映射第一人鍵盤，第二人映射第二人數字鍵盤，不能把兩支手把送進同一組按鍵。加入第二人不自動切換原版模式，需正常進入雙打。

## 快速出招契約與目前試作

- 每名玩家、每名角色各保存四個位置，沒有隱藏的第五個觸發位置。設定可留空、改選第五招、還原並重啟讀回。
- 按下觸發一次，持續按住不自動連發。切換角色、進入選單、回合結束、斷線與失焦時取消未完成序列並釋放該來源。
- 正式出招走已證實的鍵盤輸入序列，不直接寫招式狀態、跳過蓄力或保證命中。朝向由原版已驗欄位判定，不能憑玩家編號猜左右。
- 蓄力招、近身投技與空中招仍受原版狀態限制。序列時序、手動輸入衝突、同時按兩個快捷鍵與換邊中斷規則尚待窄範圍實測及操作試作，不在目前原型猜補。
- `tools/quick-moves.js` 是可撤回的設定原型，收錄八名角色的手冊候選，提供四格設定驗證、方向文字鏡像、獨立設定與按下邊緣偵測。它沒有遊戲注入功能，也沒有把未驗證的招式時序寫成正式規則。
- HTML 預覽可讀取 R1／R2／L1／L2，並顯示該玩家角色的招式名稱與指令。方向在預覽中手動選擇。設定保存在獨立的瀏覽器儲存鍵，正式設定格式未定版。

## 兩支手把雙打計畫

| 項目 | 設計與驗證 |
|---|---|
| 前置條件 | dosgolem 已有 IRQ1 make／break；仍須逐項核對第二人的數字鍵盤、Enter 與右 Shift，並從原版標題正常進雙打 |
| 玩家指派 | 兩支裝置分別選 P1、P2，同一裝置拒絕重複指派；同型號手把也以當次實際裝置分開 |
| 遊戲輸入 | 每次更新同時讀取兩人的方向、拳腳與快捷狀態，以穩定順序送入同一核心；不能輪流只讀目前設定頁所選玩家 |
| 設定與快捷 | 每名玩家保留各角色四招配置，換角色不改到另一人；角色選擇及快捷設定不解鎖原版角色 |
| 斷線與失焦 | 清除離線裝置的按住及快捷序列，顯示是哪位玩家離線；另一人的指派不交換 |
| 重連 | 正式桌面版須以裝置身分與玩家確認恢復；原型先清除離線裝置指派，要求重新選擇，避免索引重用錯綁 |
| 最小實測 | 兩人同時移動與攻擊、各自方向加拳腳、快捷互不串線、兩支同型號、USB／藍牙混用、斷線重連、選單與對戰切換 |

瀏覽器原型參考 [W3C Gamepad](https://w3c.github.io/gamepad/) 的標準配置。其裝置 index 可以在重連後被重用，裝置 id 也不保證能區分同型號的兩支手把，因此不將 index 當永久玩家識別。

目前 HTML 已提供雙人裝置指派與獨立快捷預覽；一般方向／拳腳面板只顯示正在編輯的玩家。這是設定與裝置讀取試作，不宣稱雙人遊戲路徑已完成。

## 八方向候選與輸入生命週期

斜方向先映射到說明書獨立斜鍵，例如右下對應 C／數字鍵盤 3。W+D 與 E 是否等價尚未驗證，不能自行替代。

| 方向 | P1 鍵／Set 1 make 候選 | P2 鍵／Set 1 make 候選 |
|---|---|---|
| ↖ | Q／10h | Keypad7／47h |
| ↑ | W／11h | Keypad8／48h |
| ↗ | E／12h | Keypad9／49h |
| ← | A／1Eh | Keypad4／4Bh |
| → | D／20h | Keypad6／4Dh |
| ↙ | Z／2Ch | Keypad1／4Fh |
| ↓ | X／2Dh | Keypad2／50h |
| ↘ | C／2Eh | Keypad3／51h |
| 拳 | Tab／0Fh | Enter／1Ch |
| 腳 | LeftShift／2Ah | RightShift／36h |

掃描碼名稱只是標準 PC 鍵盤的輸出候選，不代表原版消費端已逐項確認。選單須使用已驗證的 BIOS 鍵路徑，對戰使用自訂 IRQ1 的按下與放開；用狀態辨識選擇路徑，辨識失敗時停止注入並顯示原因。

原型左搖桿以八扇區量化，試用死區為 0.25，方向切換遲滯為 7.5 度，離開死區的半徑門檻為 0.30。數值只用於比較，不是正式操作定版。十字鍵優先於左搖桿也僅屬原型選擇。相反方向的原版行為及多來源合併規則仍待實測與決策。

互動稿對相反方向暫以中立顯示，只用來觀察按鈕位置。瀏覽器僅接受 `mapping=standard` 的手把；未知配置不猜索引。實體裝置、瀏覽器互動與延遲未實測，已完成的是 JavaScript 語法與靜態引用檢查。

正式注入需追蹤每個來源的按住集合。方向轉換先放開舊鍵，再按下新鍵，攻擊鍵按來源維持。斷線、失焦、切換裝置及進入前端選單時釋放該來源，不取消其他來源仍按住的輸入。關閉選單後等待實體按鍵回到中立，再接受新動作，避免確認鍵漏進對戰。

## 前端流程與完成條件

| 階段 | 操作與顯示 | 驗收 |
|---|---|---|
| 初次設定 | 選擇玩家、裝置、位置式按鈕圖、重綁、取消、還原 | 沒有手把仍能用鍵盤進出；設定獨立保存 |
| 原版選單 | 方向、確認、返回 | 短按一次只執行一次；設定與對戰路徑不串線 |
| 對戰 | 方向、拳、腳、多鍵 | 斜向、跳躍、蹲下、後退防禦、拳腳同按、蓄力、換邊招式與放開均有原版收據 |
| 暫停與說明 | 前端停止模擬時間，顯示繼續、操作、設定與離開 | 不送 Esc；恢復不跳過虛擬時間、不留下卡鍵；可取消離開 |
| 雙人與裝置異動 | 明示玩家指派、裝置離線 | 兩邊可同時操作；USB／藍牙重連不交換玩家 |

READY 前須在目前來源核對完整動作表、相反方向、多鍵、兩人輸入，以及暫停能力。正式驗收另需實體手把型號、平台、連線方式與正常玩家路徑錄影。互動稿只預覽候選，不注入 dosgolem，也不作遊戲完成證據。
