狀態：READY，限定目前固定來源的基本鍵盤輸入與已驗證招式。日期：2026-10-19。本規格不代表整份手把設計或 HD 已驗收。

後續平台訂正：使用者明確指定 Windows／macOS／Linux 原生桌面，見[規格 005](005-native-desktop.md)。下文瀏覽器入口保留作研究歷史；已驗原版輸入與招式契約仍有效，不能據此繼續把 HTTP 當玩家入口。

## 證據與適用範圍

原始 SF.EXE SHA-256 為 `24b23d41c5fe6015d211b601e44b4e030677363f7232adcf9999c9ddd80d8300`。啟動採 NOKEY.EXE /y → SF.COM → SF.EXE，不跳過標題與選角。dosgolem 為 CONTEXT 記錄的獨立來源及 IF 補丁。觀測僅使用 public oracle API。

- `workplace/input-single-v2/receipt.json`：正常單打快照的 25 組按鍵實驗。
- `workplace/input-versus-v1/receipt.json`：正常雙打選角後，Jaan 對 Jaan 的同快照 25 組輸入實驗。
- `workplace/quick-versus-v1/receipt.json`：兩名 Jaan 的天雷斬、旋風腿與十二輪詢蓄力鐵頭功，共六例均進入對應路徑 ID。
- `workplace/quick-versus-v2/receipt.json`：重跑上述六例，另以普通行走接近對手後驗兩人的過肩摔，八例均進入對應路徑。
- `workplace/input-versus-v2/`、`quick-versus-v3/`：補齊執行前工具、來源 manifest 與命令的 provenance，分別重生 25 組基本輸入及八組招式；保留先前收據。
- `workplace/ida-key-reader.json`、`ida-live-input.json`：IDA 9.4 原始運算元、bytes 及函式邊界；位址為 IDA MZ 線性，映像段 1000h。

## 已確認輸入

### 證據回填索引

不可變鍵均包含固定 SF.EXE 雜湊及 DOS 模組；資料段偏移是重定位後 DS 的相對值。舊文件的必要勘誤標記為「2026-10-19 輸入切片勘誤」。自動稽核同時檢查原始定位、舊文件與勘誤標記，缺少任一項即失敗。

| 固定模組與原始定位 | 語意 | 證據與舊規格 |
|---|---|---|
| DOS／固定 SF.EXE／DS:3EF4h、3EF5h | 兩人鍵值，已證實 | 本規格；[規格 002 勘誤](002-gamepad-design.md) |
| DOS／固定 SF.EXE／DS:3F16h、3F1Eh | 兩人方向表，已證實 | 本規格；[規格 002 勘誤](002-gamepad-design.md) |
| DOS／固定 SF.EXE／DS:16EAh、16EBh | 斬四招的限定路徑觀察，已證實 | 本規格與 quick-versus-v3；[規格 002 勘誤](002-gamepad-design.md) |

兩人各八方向、拳、腳與拳腳同按皆可由 IRQ1 按下／放開控制。雙人同時拳腳的原版輸入值為 30h、30h，放開均歸零；右側角色在雙打會回應 P2 輸入，在單打則仍走 AI。這是已證實的限定玩家路徑，不代表所有雙人角色或實體手把已驗。

| 原始定位 | 語意與證據等級 |
|---|---|
| IDA 15296h 起的原函式 | 已證實：P1 Tab→10h、左 Shift→20h；放開清除相應位元 |
| IDA 15303h 起的原函式 | 已證實：P2 Enter→10h、右 Shift→20h；放開清除相應位元 |
| 資料段偏移 3F16h、3F1Eh | 已證實：兩組各八方向鍵表，已與 runtime 原始 bytes 讀回核對 |
| 資料段偏移 3F26h | 已證實：02、06、04、05、01、09、08、0A，對應左至左上順序 |
| 資料段偏移 3EF4h、3EF5h | 已證實：兩人的目前鍵盤輸入值，按鍵收據可重播 |
| runtime IRQ1 01B9:524C | 已讀回原始 prefix `1E 56 51 50 53 B8`；MOV AX 的重定位值用來取得實際資料段，不能照抄 DAME 少了 PUSH BX 的版本 |
| IDA 13C38h 起的原函式 | 已證實：以 ds:12ACh／12AEh 角色索引讀相應資料檔；前端只讀，不改寫角色 |
| IDA 15D9Fh | 已證實：原版對戰迴圈開始；在此安排快捷輸入，保留核心輪詢順序 |

同時按相反方向及多來源不同方向的正式整理方式尚未定版。本切片保留原版掃描碼處理，不增加 SOCD 規則。相同掃描碼有多個輸入來源時，由前端追蹤擁有者，最後一個來源放開才送 break。

## 快捷輸入切片

僅對已驗證角色與招式啟用實際快捷。每名玩家仍保留最多四格設定；未知角色、未知招式、未知朝向或不在對戰時，明示拒絕執行，不改寫原版狀態。

| Jaan 招式 | 輸入階段，面向右 | 證據 |
|---|---|---|
| 天雷斬 | 右一輪詢、右下一輪詢、下＋拳一輪詢 | P1、P2 原版路徑均為 24h；P2 依朝向反轉左右 |
| 旋風腿 | 下一輪詢、左下一輪詢、左＋腳一輪詢 | 兩人原版路徑均為 23h |
| 鐵頭功 | 下十二輪詢、上＋腳一輪詢 | 兩人原版路徑均為 22h；十二是已驗充分條件，不宣稱原版最短蓄力時間 |
| 過肩摔 | 前＋拳一輪詢，須近身 | 以正常行走接近的兩人路徑均為 25h；快捷本身不自動接近對手 |

前端以對戰迴圈安排階段，按住不連發。輸入一個快捷時，取消該玩家先前的快捷；新的手動按鍵、回合離開、斷線、失焦及暫停取消快捷並釋放該來源。這是可撤回操作試作的衝突處理，正式完整操作驗收仍依規格 002。

投技已在正常行走接近的條件驗證；不為一鍵投技自動走近對手或注入座標。其他角色的招式設定可以保存，未驗證的招式不能送進正式遊戲路徑。

## 本機操作入口

先提供本機瀏覽器研究入口，核心仍在 Docker 內執行。這不是公開網站或正式平台承諾。畫面只讀，選單走 BIOS／滑鼠，對戰走 IRQ1。原版資料唯讀，寫入只進獨立 scratch。

- 前端暫停停止執行核心，不發 Esc，不累補暫停期間的時間。
- 瀏覽器隱藏或逾時沒有心跳時暫停並放開輸入；裝置斷線只清該來源。
- 原貌始終可用。HD 來源／姿態還未證實時保留原貌，不能把靜態概念圖覆蓋整場動態遊戲。
- 輸出版本、來源、原始輸入與程式雜湊可回查。即時人為操作不作決定性原版對拍收據。

## 驗證界線

整合後需從正常入口驗標題、雙人選角、同時移動／攻擊、快捷、釋放、暫停及失焦，不以載入戰鬥快照代替正常玩家路徑。合成 API 測試與實體手把、瀏覽器 GUI 驗收分開列。完整回合、返回、音訊與正式速度仍待驗；未通過前不把本規格標為完整 CONFORMED。
