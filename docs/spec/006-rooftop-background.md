## 顯示契約與限制

現行 dosgolem mode 13h 的 `Indexed()`／`ScreenRGB()` 回傳 A0000 起的線性 320×200，尚未套用 CRTC 起點。DS:1334h 的硬體垂直控制值另行保存，不能直接當作此 API 的裁切。本切片與目前原貌入口使用同一份 API 畫面，顯示來源裁切 Y 為 0。此為執行器的既有畫面契約，不宣稱實機 CRTC 捲動與震動畫面 parity，也不改寫 CRTC 或原版資料。

## 呈現契約

- 原貌為既有基準；以選用的 `-hd-assets` 載入本機素材。提供「HD 背景」切換，沒有素材時保留原貌，不影響鍵鼠或手把。
- 在原版完成顯示拷貝後保存只讀色號、色盤、相機及角色 metadata；原貌與 HD 使用同一快照。切換不呼叫 Step、載入狀態或釋放操作來源。
- 只支援 scene 4、固定背景 RAM 雜湊、已驗範圍的相機及原始背景色盤。未知場景、來源不符、淡入淡出色盤或素材損壞時整張退回同一快照的原貌。
- 背景沿 480×204 邏輯來源與相機位置裁切，直接將高解析屋頂素材畫入目前 960×600 遊戲區，不縮回 320×200。正式倍率與像素比例仍未定版。
- 原始畫面的上方 48 列完整保留。其他像素只有在色號小於 128 且與原始背景同位置相同時才可透出 HD；其餘原始像素全部保留，包含角色、陰影、攻擊、特效及訊息。
- 本切片沒有替換角色圖。未知角色姿態仍使用當幀完整原貌，不以一張待機圖代替走路、攻擊或受擊。
- 兩名玩家的原生手把、基本輸入及已驗快捷沿用原介面與核心。呈現切換不改變按住狀態、動作條件、傷害或原始亂數。

## 本機資料與驗收

實作入口為 `internal/gamecore/presentation.go`、`internal/hd/background.go` 與 `internal/desktop/game.go`。`tools/prepare_hd_background.py --output <新輸出目錄>` 在 `sc-cht-hdtools:pillow11.3.0-r1` 容器的 `/project` 執行，準備資料；輸入是 `workplace/hd-source-probe-v3/I2.XGB.png` 與 `workplace/hd-layers/rooftop-layer.png`。輸出目錄須尚未存在，避免覆寫研究素材。現有本機包為 `workplace/hd-rooftop-study/`，玩家程式用 `-hd-assets` 指定，預設維持原貌。

研究素材放在 workplace，manifest 版本 1，記錄原始檔、完整像素／色盤／HD PNG 雜湊、邏輯尺寸及來源收據。載入先核對版本、相對檔名、大小、雜湊、PNG 尺寸及完整素材群組；不完整時不顯示半套背景。素材含原版衍生內容，不內嵌程式、不加入公開包。

驗證涵蓋正常雙打選斬與法蘭克、待機／走動／跳蹲／拳腳、同狀態原貌與 HD、未對應場景回退、設定與快捷不受影響、兩人輸入及三平台建置。實體雙手把與 macOS 真機仍分開驗收。原版執行器的畫面契約、HD 美術幾何偏差及完整角色動畫限制均保留，不由綠色單元測試升格為完整原版對拍。

本輪收據為 `workplace/hd-native-v2/receipt.json`、`comparison.json` 與 `workplace/hd-fallback-v1/receipt.json`。屋頂正常 GUI 十項、道場九項通過；`tools/verify_hd_capture.py workplace/hd-native-v2` 在上述 Pillow image 中核對 GPU 輸出，190,818 個 HUD／高色盤前景輸出像素逐點保持原貌，385,169 個背景輸出像素改變，切回 HD 的遊戲區相同。`internal/hd/background_test.go` 另驗 16 個原始完整畫格及錯誤來源、相機、色盤和損壞素材。
