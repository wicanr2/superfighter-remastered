## 證據與範圍

- SF.EXE SHA-256 為 `24b23d41c5fe6015d211b601e44b4e030677363f7232adcf9999c9ddd80d8300`；NAME.XBB 為 `60c0bbe367e44ab9fda512df2ba93ad62d70147df90079d07ff15818f21bad82`。其餘固定 HUD 原檔與色盤契約沿用 010，不新增來源版本。
- IDA Pro 9.4 的 `workplace/ida-hud-v2.json` 保存 MZ 映像線性位址的 `sub_133F4`。`0x1346D..0x13481` 讀 NAME.XBB 指標表 byte 16h 的圖像，每個左側勝場在 8006h 加 12×序號處繪製；`0x134C5..0x134D9` 右側從 8130h 減 12×序號處繪製。這些是 IDA 位址，不與 DOS runtime 或檔案偏移混用。
- NAME.XBB 指標索引 11 指向檔案偏移 8384，header 10×12，後接 120 bytes，其中 93 點非零。已解碼為向上的拇指圖示。其原圖與來源檢查保存在 `workplace/hud-wins-glyph.png`、`workplace/hud-wins-evidence.json`，由 [獨立證據工具](../../tools/hud_wins_evidence.py) 產生。`workplace/hud-wins-review.json` 審查固定來源、兩段唯一原指令 bytes、33 個逐點一致的真實 fixture、顯示鎖存差異及四個靜態邊界後升 READY。
- 原版顯示勝場在介面 setup 完成時鎖存，不能用較早變動的規則勝場提前顯示。沿用 010 的只讀 HUDState.DisplayWins、完整 bitmap／色盤／最後覆蓋核對，不增加原版記憶體讀寫或新觀測點。
- 正常 `hud-draw-v3` 的 `hud-0986` 有左側一勝，其餘 fixture 包含尚未顯示的規則勝場。右側及第二圖示的位置有靜態程式證據；尚無本輪正常 GUI 實際勝場樣本，不能稱為全部玩家／勝場的動態驗收。

## 呈現契約

- 左側第 n 個圖示安全矩形為 `(6+12n,0)..(16+12n,12)`；右側為 `(304-12n,0)..(314-12n,12)`。n 從 1 起，最大 2。實際畫面 Y 加原版 HUDState.Rows，再依既有 viewport 比例縮放。
- 每個圖示直接以原生向量路徑重繪金色拇指、深色描邊與手指內線。使用目前 HUD 的金色調；曲線直接在實際輸出解析度繪製，不放大原版點陣或改用獎盃／星星。兩側沿用同一方向，不自行鏡像。
- 向量筆畫與抗鋸齒須落在該安全矩形內。圖示數量只讀 DisplayWins，為零時不繪製，不提前使用 Wins。重繪不改遊戲、輸入、時序、亂數、原版色盤或存檔。
- HUD.Select 原有來源與完整覆蓋全部通過後，才把本次勝場矩形加入 Replace。移除原圖時仍逐點使用已證實的 HUD 非零覆蓋，還原同格 Underlay，再畫 HD。不得抹除整個固定矩形而刪掉背景／人物。
- 不新增素材清單、設定或存檔版本，不改啟用條件。舊版角色群組及未知／損壞來源沿原有完整原貌回退；原始圖層保持可獨立重組。

## 升 READY 與驗收

1. 獨立工具核對固定原檔、IDA 匯出的來源身分與關鍵原指令 bytes，保存各自位址基準與輸出雜湊。
2. 重建全部 33 個 HUD fixture，核對勝場圖像位置與非零寫入；把正常動態樣本與靜態導出的兩側 0..2 邊界分開記錄。通過並審查後才升 READY。
3. 正式實作後驗 33 個真實 fixture、勝場鎖存及零勝不替換；原有損壞拒絕、舊素材回退及來源不變檢查繼續適用。
4. 正常原生完整對戰取得第二回合的一勝畫面，獨立重組、原貌／HD 暫停切換及勝場區域比對。不得以強制勝利、改生命或直接注入勝場代替。
5. 三平台重新建置並驗實際編譯輸入。Windows Wine 與真機分開記錄；本切片通過不代替完整 HD、其他介面及實體手把。

自有向量程式依專案授權，原版 glyph 與含原版內容的證據只留本機，不加入一般發行包。

## 已完成的限定驗證

`native-win-markers-v1` 由正常標題、選角、普通移動與拳擊取得第一人首勝，七張擷取的原版六層均可逐點重組。三張暫停的核心、色號、色盤、快照及即時 RGB 相同，HD 恢復後的遊戲區逐點一致；勝場區已替換為高解析向量拇指。`win-markers-checks-v2` 全套測試與 go vet 通過，33 個 HUD／19 個特效 fixture 沒有跳過；`win-marker-coverage-v1` 另驗全部非零 HUD 像素與未獲勝區域。

四個平台／架構二進位均已重新建置。正常完整雙打、結果及返回標題由另存的 `native-match-v2/build-baseline` 證明，該版與勝場版的核心來源相同，但不把基準二進位改稱目前版本。右側及第二圖示、勝場版 Wine 與實體裝置仍未作正常 GUI 勝場驗收，因此保持限定 READY。
