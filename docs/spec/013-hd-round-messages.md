- `sub_13635`，runtime 3635h，只有來源非零才寫入 `色號 OR A0h`。來源 DS 每列加 6 段、目的 ES 每列加 14h 段，分別相當於 96／320 bytes。runtime 3666h 是返回點；此次呼叫的堆疊返回值為 3599h。

- 開場主迴圈 `sub_15CFD` 呼叫 runtime 3E09h 的背景拷貝、陰影、人物、HUD、3570h 訊息及 3E5Ch 顯示。3E09h 從 DS:1334h 指定的列開始複製 192 列；第一回合觀察值為 12。頂端未覆寫列保留合成段既有 bytes。這與一般背景從第零列覆寫的 3DE4h 不同。

## 呈現契約

- 快照保存繪製前的回合索引、階段、半寬、來源 bytes／雜湊、窗口與完整旗標，以及最後 raster 在訊息前的底層。只觀測原版；不寫狀態、不改聲音或輸入時序。
- 訊息 helper 返回之後，階段 1、半寬 4 的原常式仍會把 FIGHT 暫存圖複製到合成段前 1442 bytes。這些頂列變更須保留原貌，只移除中央訊息的已核對像素。完整旗標等到 runtime 3634h、整個常式返回前才成立。新增 v3 的全常式覆蓋實驗，不能以 v2 的 helper 結束點冒充此範圍。
- 開場背景另保存未覆寫頂列。完整圖層重組必須與原版線性 320×200 畫面逐點一致；未覆寫內容不能補成零或當純背景。原背景來源核對只跳過明示的保留列，這些列須另以原貌不透明像素呈現。
- 開場背景入口只接受已驗的 12 列保留。背景層先以此次拷貝前的頂列 bytes 與不透明基底初始化，再觀測 3E09h 到 3E43h 的實際寫入。快照以 `retained_background_rows` 明示此基底，不冒稱頂列是本次背景寫入。一般對戰入口仍逐寫記錄整張背景。
- 逐檔驗證來源與 BOARD 色盤。依原檔重建全部 1442 bytes，核對實際窗口、最後 raster 的寫入值與覆蓋。未知欄位、來源、位置、圖層次序或色盤整張退回原貌；不能只刪掉中央矩形。
- 原生高解析字圖沿用 HUD 的內嵌字型、金色字與深色描邊。固定安全矩形為原座標 `(112,56)..(208,71)`，包含字圖描邊。每格直接裁切已觀測的橫向窗口，不新增補幀或動畫計時。ROUND 數字來自繪製前索引加一，FIGHT 的驚嘆號保留。
- 僅在已驗新版角色／特效素材群組啟用，既有原貌／HD 切換保持同狀態。舊素材與缺件維持完整回退。設定、存檔、原版資料與素材清單格式不變。

## READY 與驗收閘門

回合索引有效範圍 0..8、階段 0..3、半寬 4..68 且為四的倍數，均依上述原始控制流與數字表限制。後續回合索引有靜態來源組合證據，但正常動態驗收只涵蓋索引 0。

READY 前須核對 v2 部分背景來源與頂列保留，記錄來源與腳本雜湊。正式接入後，驗原檔獨立重組、四階段窗口、錯誤來源／位置拒絕、原版狀態開關觀測一致、正常 GUI 的開場與切換、正式對戰清除訊息，以及四平台中間二進位。GUI 必須使用普通選單路徑；暫停與步進僅作前端控制，不注入原版座標或階段。

原版硬體捲動仍依 [006](006-rooftop-background.md) 與既有 oracle 線性畫面限制記錄，不在本切片改 CRTC 語意。實體平台與手把驗收分開記錄。原圖、字圖與含原版內容收據僅留本機，程式碼與規格可依專案授權保存。

## 已完成驗證與限制

- `round-core-compat-v1` 比較 1,508 個觀測開關邊界，狀態、原貌及實時 RGB 一致；保存全部 66 格開場，四階段、十二種窗口及末格暫存拷貝可由原檔與完整圖層獨立重組。正式對戰後訊息與保留列標記清空。
- `round-checks-v3` 全套 go test 與 go vet 通過，沒有跳過；66 個真實開場 fixture 另驗 HUD、陰影仍可選取、錯誤來源／窗口／色盤／覆蓋拒絕，以及原圖層不變。跨平台 image 預設關閉 cgo 的兩次編譯失敗屬工具環境；既有 Linux image 明示 cgo 後乾淨重跑。
- `native-rounds-v1`／`windows-rounds-v1` 各七項與十張具名擷取；每側六張原生字圖 GPU 擷取的窗口外像素完全不變。部分 ROUND、完整 ROUND、FIGHT 三組暫停原貌／HD 切回逐點一致，進正式對戰後清除訊息。Wine 不代替 Windows 真機。
- `native-round-battle-v1` 十七項及十五張完整原貌重組、十二張陰影合成通過；`native-round-legacy-v1` 十三項、十一張具名擷取及缺件整張原貌通過，未加入新版開場字圖。
- 四個開場版二進位的實際編譯輸入、原檔、執行器副本、上述來源及 GUI 證據由 `tools/audit_native_rounds.py` 核對，輸出 `workplace/native-rounds-audit.json`，依此限定升 CONFORMED。完整比賽、後續回合及其他文字不由此自動升格。
- 開場頂端可見的資料列源自 oracle 的 CRTC 起點限制，仍待處理。這是本輪截圖已確認的限制，不能以保留原貌視為畫面品質完成。
