## 資料與顯示契約

- 在專案獨立正式副本新增已驗候選的四檔，原有 1715 檔 bytes 不變，保留舊 manifest 為 v2。共用 dosgolem 與原版資料仍唯讀。`go.work` 路徑不改，僅對此專案副本擴充能力。
- 桌面明示啟用新的只讀顯示快照。完整 battle frame 同時保存原 64,000 bytes、原圖層、額外 1,536 bytes VRAM 尾端，以及 `LinearScanout` 的幾何與實際可見色號。原來源與顯示輸出分開；舊 RGB／Indexed API 不改。非對戰則由即時顯示快照呈現，離開對戰清空舊快照。
- 使用既有 960×600 遊戲區與每原像素 3×3 的倍率。320×192 以 960×576 居中，頂底各留 12 個視窗像素；320×200 與舊位置相同。這保留目前開發版的等比像素單位，正式像素比例與預設模式仍未定案。
- HD 維持原 VRAM 座標合成，整組畫面使用同一個映射：`視窗 y = 可見區頂端 + (VRAM y - 顯示起點列)×3`。背景、人物、特效、HUD、勝場、陰影與 ROUND／FIGHT 全部套用，不個別挪動。圖層與原始覆蓋不改寫。描邊與裁切仍在原安全矩形，最終再裁到真正可見區。
- 只有寬 320、高不超過 200、列距 320、起點整列對齊且視窗結束不超過原背景 204 列時可啟用 HD。原可見區超出第 199 列的部分，逐點比對快照的真實尾列與已驗背景原索引及色盤，吻合才繪製完整高解析背景尾端。未知尾端、來源、相機或色盤使整格退回同一快照的完整原貌。
- 原貌直接呈現真正可見的色號，不裁掉十二列後拉伸 188 列，也不補零或用舊畫格填尾列。未知 oracle profile 保留明示未映射的原貌基準，不啟用 HD，並顯示限制；不能冒稱已完成顯示映射。
- 菜單滑鼠以實際可見矩形換算顯示像素；現行 320×200 標題坐標不變。外圍設定、快捷、手把、鍵盤、暫停與存檔保持原契約。映射不執行指令、不寫原版狀態。

## 擷取與核對

F12 同時保存原 VRAM 圖層與尾端、真正顯示色號、可見矩形及合成原點。GPU 陰影／字圖的擷取須標明原點或對應可見區，不能把原 VRAM 座標當已投影座標。保留舊版無顯示 metadata 的驗證分支，歷史收據不換名。

1. 核心正常選單的 66 個完整開場與正式對戰快照：原 64,000 bytes／原圖層不變，新增顯示色號可由原資料與尾端獨立重組，關閉觀測與開啟的原版狀態相同。
