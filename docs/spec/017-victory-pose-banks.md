# 017：勝利姿勢的獨立圖像來源

狀態：CONFORMED，限定來源區分、相容讀取、斬／法蘭克勝利姿勢登錄及斬首勝原生呈現。日期：2026-10-19。七張透明姿勢已核對；第一人正常首勝與舊素材回退通過。第二人與完整勝利動畫仍待驗收。

## 玩家阻塞與來源

規格 016 的正常首勝已有完整 WIN 圖層，但整張 HD 在人物來源驗證時拒絕。`victory-core-diagnostic-v1` 保存實際斬勝利格：動作槽為 3，實際圖像為 46×89，SHA-256 `8fe892413a8c7eed1bc5aa14eed38bb7a6b36dc72f9c084a98269c31ef8a5298`。一般 `SFMAN01.DAT` 的槽 3 是另一張 86×89 圖，不能替換使用。

輸入 EXE 沿用固定 SHA-256。IDA 9.4 的 `sf-victory-v1.i64`／`ida-victory-v1.json` 保留 `sub_137A3`、`sub_13883` 的原始指令、名稱與位址；`sf-victory-v2.i64`／`ida-victory-v2.json` 補齊原人物繪製端。工具與 MZ／runtime 位址空間沿用規格 016。

| 原始定位 | 證據等級與語意 |
|---|---|
| IDA `0x137A3..0x137FC` | 已證實靜態控制流：依角色讀 `[SI+404Ch]` 所指檔案，seek 60h，將 120h bytes 讀入 DS:1706h，再從 180h 起讀入 DS:132Ah 的圖像段 |
| IDA `0x13883..0x138DC` | 已證實靜態控制流：第二人用相同格式重載 DS:1826h 與 DS:132Ch |
| IDA `sub_141FA`／`sub_1439B` | 已證實：原動作槽仍由 DS:16F2h／16FAh 讀取，經當前 72-entry 表選來源；槽號本身不等於固定 SFMAN 圖像 |
| `AAWIN.FIG` | SHA-256 `0c332b13bb923116460a7fa8cf474b105d8f1d2b180a8d7ede5af6f92209f8f7`；72 個有效入口、四個不同來源。槽 3 的完整 bytes 與正常首勝捕獲完全相同 |
| `FFWIN.FIG` | SHA-256 `2a353085e1ad73d5521bf1c87e45f5678c2d2cd59148f50e291aad6995b3c9c3`；72 個有效入口、三個不同來源，正常第二人勝利姿勢的逐格來源仍另驗 |

最初把 60h／180h 套到 SFMAN 檔的解析假設已被無效指標與來源雜湊否定；它只適用 WIN 圖像檔。保留原槽號及來源位址，不把勝利槽 3 改名成一般槽 3。

## 接入契約

- `Sprite` 增加可選 `source_bank`，空值沿用一般來源，`victory` 表示已核對的 WIN 表。保留原槽號、原來源 SHA-256、尺寸、定位與繪製旗標。以實際 RAM 指標表與原檔表的逐字比較辨識來源；未知表不得猜成一般來源。
- 角色素材清單擴充為版本 3，來源記錄與姿態都明列 `source_bank`。一般動作與特效仍用原 SFMAN 來源，勝利姿勢用 WIN 圖像檔；圖像來源與色盤群組分開。讀取器維持版本 1／2 相容，未知來源或缺件仍整格原貌。玩家設定格式不變。
- 首批補齊斬四張與法蘭克三張 WIN 姿勢；其餘入口以原檔相同 bytes 登錄，保留別名表。沿用已確認的街機手繪風格與既有人物造型；透明 PNG、提示詞、原圖與雜湊只留本機。
- 原版仍決定勝利動作、動畫、時序與流程。登錄圖像來源不新增動作、不改碰撞，也不把讀取器接受全部槽稱為完整動畫驗收。

## 已審核的來源與格式

- 已證實 EXE 檔案位移 58972 的十一個 word，逐一指向 AA／BB／CC／EE／FF／GG／HH／II／JJ／DD／KK 的 WIN.FIG 字串。其 DS 檔案基底為 42512，與原 DS:404Ch 表定位相同；這是 EXE 檔案位移，不能當作 runtime 位址。兩個已用 WIN 檔首 96 bytes 與各自 SFMAN 的 AC8h 色盤相同。
- `Sprite.source_bank` 由原始 RAM 72-entry 表與原檔表逐字匹配判定；一般來源以空值保持舊收據契約，勝利來源為 `victory`，無法對應為 `unknown`。不根據畫面看起來像勝利、動作槽號或勝負旗標猜來源。
- 版本 3 的 `CharacterSource` 與 `CharacterPose` 增加可選 `source_bank`。來源鍵為角色及圖像群組，姿態鍵再加原槽號及色盤群組。一般表／資料基底為 B28h／C48h，勝利表／資料基底為 60h／180h；每項仍核對原檔、完整圖像 bytes、SHA-256 及圖集。勝利圖像只使用原正常色盤，與第二色盤特效分開。
- 版本 1／2 保留讀取及原回退；新清單不取代舊資料。版本 3 是目前本機試作資產格式，玩家設定與原 DOS 資料不變。未知圖像群組、混用勝利／特效色盤、重複來源、缺件及來源不符一律拒絕整格 HD。
- `workplace/victory-poses-v1` 保存 144 個有效入口、七個不同來源及全部別名。`workplace/victory-art-v1` 的兩張生成 PNG 已目視；斬四格及法蘭克三格的透明分隔、外緣、RGBA 與雜湊已核對。使用內建 image_gen；精確提示詞及參考路徑在 requests.json，保留原輸出 bytes。
- 原生基底 5c1bf7c 已另存。版本 3 的 `hd-characters-study-v8` 已登錄 301 個姿態鍵，其中 WIN 來源 144 個入口對應七張不同姿態。來源、字圖、舊素材隔離及全套 Go 測試已通過；正常首勝的 1,479 個核心比較邊界、Linux／Wine 原生視窗及舊素材整格回退亦通過。不能把來源槽齊全稱為完整動畫已驗。

## 驗收

1. 原檔 144 個 WIN 表入口全部界限檢查，四／三個不同來源與正常首勝實際 bytes 核對。
2. 來源、姿態、色盤、圖集、透明邊界、別名與未知來源拒絕測試；舊版素材的回退另驗。
3. 依規格 016 的正常核心／原生首勝與切換驗證，證明 WIN 字圖及勝利人物同格 HD。第二人與完整勝利動畫覆蓋另列，不能由第一人樣本外推。

上述限定範圍已由 `victory-core-compat-v2`、`native-victory-v1`、`windows-victory-v1` 及 `native-victory-legacy-v1` 通過，細節與 GPU 核對見[規格 016](016-hd-victory-messages.md)。正常首勝保留原槽 3 並辨識為 `source_bank=victory`；獨立核對重新解析 WIN 原檔，不靠角色名或勝負旗標猜來源。

研究入口為 `tools/victory_pose_reference.py`。本機原始來源、PNG、研究收據與二進位不公開散布；規格及自有工具可依專案授權保存。

## 兩側正常勝利姿態取樣

- `victory-animation-jaan-v1` 取得 5,293 個成對比較邊界，13 個 WIN 快照取樣，涵蓋斬的槽 0／2／3。`victory-animation-frank-v1` 取得 5,534 個邊界，8 個 WIN 快照取樣，涵蓋法蘭克槽 0／2。全部取樣的圖層完整、角色來源可選；五種來源的固定畫格另由原檔、HUD、陰影及背景獨立重組。
- 取樣在回合結束後以每 10,000 個指令步進觀察，保留 serial、counter、來源與文字前後狀態。這證明所取樣的動畫來源對應，不能稱原生逐格連續動畫已驗；兩人的槽 1 仍只有原檔與靜態登錄證據。
- Linux 第二人首勝已呈現抱胸槽 2 與 FRANK WIN。Wine 第二人案例仍在重跑，其完成前不擴大兩平台正式驗收範圍。新角色候選來源另見[規格 018](018-sarkov-hd.md)。
