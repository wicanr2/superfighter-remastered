狀態：CONFORMED，限定已驗的一般姿態、正常色盤與戰鬥姓名。日期：2026-10-20。Linux／Wine 正常操作與切換各七項、九張擷取，以及 Linux 缺件九張整格回退通過。沿用[一般角色契約](018-sarkov-hd.md)與[版本 3 來源群組](017-victory-pose-banks.md)，不改資料格式、設定或玩法；完整角色 HD 仍未完成。

## 已有證據

- `bullet-source-v1` 從固定原始包的 SFMAN03.DAT 解碼 72 個一般入口、58 組不同 bytes，保留原槽與別名。格式仍為檔案 B28h 的表、C48h 的圖像基底及 AC8h 正常色盤；固定輸入與完整 SHA-256 見 `workplace/bullet-evidence-review.json`。
- `hd-frame-bullet-v1` 由正常標題及選角選 2／4 雙打。124 個完整畫格的兩人實際指標與圖像 bytes 均吻合原檔，背景 RAM 均吻合 I2 屋頂。涵蓋角色 2 的 15 個一般槽，不外推完整動畫。
- 原 NAME 槽 2 為 `BULLET`，62×11，檔案偏移 05C8h；完整字圖 SHA-256 `fcbd1dcf514526450e7588972384ed34896a601c1a9e432764fd664ab0e362c8`。設定 ID 為既有 bullet，中文名為子彈，不改設定目錄或角色識別字。
- 原圖為藍紫色連帽運動服、黃色側線、白色手部纏布及白色長靴，頭臉藏於帽內。五張內建 imagegen 透明 PNG 對應 58 個不同姿態；槽 41 保留原圖的全藍受擊閃光與黃色外線，不改成一般配色。PNG 與精確提示詞在 `workplace/bullet-art-v1`，原 PNG bytes 不變。
- `hd-characters-bullet-candidate-v1` 以 445 鍵薩爾可夫勝利候選為基底，追加 72 個一般入口，共 517 鍵、25 張 PNG。基底的原生勝利仍在驗證，不能把候選數量當成兩個角色均已正式驗收。

## 接入與驗收

1. Go 嚴格讀取器核對全部 72 槽、58 組來源、實際 124 格 consumer 與舊基底不變。原始字圖來源及造型另以正常畫面目視核對。
2. 只補已解的角色 2 戰鬥姓名 `BULLET`。矩形由 NAME 槽 2 的 62×11 導出，人物、屋頂、陰影與 HUD 必須同格驗證後才切 HD。其他姓名白名單不擴充。
3. Linux／Wine 由正常選角驗普通行走、蹲、跳、攻擊及原貌切換，核對來源與核心／設定不變、恢復逐點相同。缺角色 2 的舊素材須整格原貌，不能只有介面變 HD。
4. 三平台四份編譯產物及精確來源核對，存檔與雙人快捷設定維持原格式。未驗快捷繼續拒絕，不因有四格標籤就啟用。

WIN、第二色盤特效、受擊替代色盤、未支援幾何與完整動畫另驗，未知或缺件沿用整格原貌回退。原版、衍生美術及研究收據只留本機；自有規格、工具與測試依專案授權保存。

首項由 `bullet-candidate-checks-v1.log` 通過，目視原版正常畫面及 NAME 字圖確認 `BULLET`／62×11。接入後 `bullet-integration-checks-v1.log` 的完整程式套件測試與 go vet 通過；`bullet-hud-checks-v1.log` 使用真實原生 HUD，核對名稱、矩形及未知角色拒絕。

`native-bullet-v1`／`windows-bullet-v1` 各九張擷取經 [一般角色核對工具](../../tools/verify_sarkov_capture.py)的 `--player0 2` 完整重組。各自的暫停三張來源／核心／設定相同，恢復 HD 的遊戲區逐點一致；不稱跨平台同狀態。Linux 範例的子彈輸出變動 18,567 點、姓名矩形 6,138 點，字形另由實際標籤與目視核對。`native-bullet-missing-v1` 的九張全部等於原貌，證明缺角色 2 時沒有只切換介面。

四個二進位沿用精確 35 份編譯輸入，ELF／PE／兩種 Mach-O 已核對；Wine 不代替 Windows 真機。薩爾可夫勝利基底另保留版本身分，020 的一般角色驗證不補足 019 尚缺的 Wine 下一回合收據。
