# 032：練習模式

狀態：CONFORMED，限定下列抽樣範圍。使用者於 2026-10-20 授權新增練習模式，雙方鎖血、時間停止、電腦不主動動作。

## 玩家契約

- 工具列新增「練習：關／開」，F9 與 `-training` 使用相同開關。選單及選角時可預先開啟，仍用普通單打／雙打入口選角色。
- 在可操作回合的下一個完整邊界啟用。雙方補滿至原版 124，清除待扣傷害，時間停在啟用時數字。開關不暫停整個模擬器。
- 電腦的決策輸入清為中立，保留原版受擊、擊退、倒地及已開始動作的收尾。雙打兩人仍能操作，兩支手把的既有指派不變。
- 關閉即停止介入。生命從當下滿血繼續扣、時間從凍結值繼續倒數，AI 使用原版決策。已造成的回血不倒帶。
- 擊倒／時間歸零已成立的回合不救回；顯示等待下一回合。開關只存於本次執行，重啟預設關閉，除非帶 `-training`。
- 診斷及截圖標示 requested／active／modified。本次曾啟用即保留 modified，不能把練習模式收據稱為未修改原版對拍。

使用者已回覆「雙方補滿並鎖住滿血」，此項為確認決定。

## 邊界與失敗

原始檔唯讀，不修改 SF.EXE／SF.COM／AIDATA。訓練寫入只在適配層及明示開關內。HD 只讀呈現層不加入寫入。
滿血來源尚未取得、資料段或回合狀態不符時，不猜圖、不介入，保留 requested 等待；診斷標示未 active。
生命已為零、待扣傷害已達生命、擊倒旗標不為零或時間已零時，等下一回合。不能清除既成擊倒來強行續戰。

## 驗證閘門

1. 用正常 NOKEY → SF.COM → 標題 → 選角進場；從同一機器快照分支做 baseline／訓練對照，記錄受控狀態與工具身分。此為功能差異實驗，並非原版 parity。
2. 單打確認 AI 消費端中立、對手不主動移動；計時不變，輸入與受擊仍前進。
3. 雙打以普通雙方拳腳命中，確認兩側有實際命中且生命維持 124、待扣傷害為零；關閉後扣血與倒數恢復。
4. 預選、暫停、回合已結束、退出及重新啟動不遺留寫入；未啟用與原版普通執行的狀態／畫面一致。
5. Linux 原生正常工具列與 F9；Windows／macOS 編譯驗證。Wine 與實體手把／macOS 真機分開列明。

## DRAFT 審查

`workplace/training-evidence-review-v1.json` 綁定 IDA 匯出、v3 探針程式與收據的 SHA-256。兩種模式皆由普通選單進入，Save／Restore 固定分支初始機器狀態，包含繼承亂數狀態；不宣稱內部 seed 數字已解出。

- 單打鎖血 124／124、時間 98、右側命中三次，AI 消費非中立輸入為零；關閉後 AI 非中立 127 次，時間 89，第一人正常被擊倒。
- 雙打兩側各命中三次、生命 124／124、待扣零、時間 98；關閉後生命 99／99、時間 85。
- v1 同時攻擊只有一側命中，v2 關閉後正常擊倒卻仍等活動畫格，兩者都是探針輸入／終止條件問題。v3 分開攻擊並在正常擊倒後停止；舊探針及失敗未覆寫。
- BOARD.XBB 為 10,240 bytes，SHA-256 `a1b789d9187f77c70b28a5dfe782af258f6a84c6260ac4b20e55817e0c00b7ff`，兩個滿血矩形均非清空顏色。正式實作直接讀固定原檔，避免依賴啟用前曾擷取滿血畫格；另用既有 HUD Reference 獨立核對 bitmap。

據此將規格由 DRAFT 升為 READY，後續結果見下節。
