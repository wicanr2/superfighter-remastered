# 035：鍵盤組態與四格出招鍵

狀態：限定 CONFORMED。使用者明確要求鍵盤可組態並定義快速出招鍵。沿用既有雙人、逐角色四格招式配置與原版輸入，不變更玩法。

## 來源與授權

基本動作與斬四招的已證實原版來源沿用[004](004-live-input-slice.md)，固定 SF.EXE SHA-256 為 `24b23d41c5fe6015d211b601e44b4e030677363f7232adcf9999c9ddd80d8300`。八方向輸出為已驗 Set 1 掃描碼；快捷仍呼叫 Core.Quick，未知角色／招式明示拒絕。這次只增鍵盤觸發與設定，不把手冊中的其他角色招式當成已驗。

使用者另指定三名魔王可選、三平台打包與 Release。既有 025 單／雙打十一人選角保持，發行依 036，不將這次功能解讀成完整 HD 完成。

## 設定契約

- 每人八方向、拳、腳與四個快捷鍵，共十四欄。保留舊方向／拳腳預設；Enter 作第二人拳時沿用 NumpadEnter 別名。第一人四快捷預設主鍵盤 1／2／3／4，第二人 7／8／9／0。
- 鍵盤與手把共用每人每角色四格招式。鍵位是每人一套，不隨角色改動。每格可留空，招式仍可選第五招取代其一，維持最多四格。
- settings.json 版本 1 增加可選 keyboard 欄位，兩列、每列十四個鍵名。舊檔未含此欄時只補鍵盤預設，保留既有角色設定；讀取不回寫。未知鍵、保留鍵、錯誤列長及跨兩人重複鍵拒絕，壞檔不覆寫。
- 按下觸發一次，按住不連發。基本動作繼續走原版掃描碼，沒有新增 SOCD 或斜向合併規則。鍵盤、手把與快捷的來源所有權沿既有適配。
- 暫停、失焦、設定與練習模式切換清除輸入並等待中立；設定捕捉不送進遊戲，Esc 取消，Delete 清空，兩人鍵盤可還原。Esc、F9、F10、F11、F12 為前端保留鍵。

## 原生介面與垂直鏈

沿用 F10 設定面板的雙人欄位與字體，增加鍵盤頁。選欄位後按 Enter 或滑鼠開始捕捉；Tab／上下切欄位，F8 切換手把／鍵盤頁。等待啟動捕捉的按鍵放開，才收新的按鍵。衝突保留舊綁定並顯示原因，不擅自交換另一人的鍵位。

鍵名 → 受驗設定 → 每人固定原版輸出 → 既有輸入與四格招式 → 原生 UI → 原子保存及重啟讀回。未新增原版存檔欄位，原檔唯讀。

## 驗收

純測試驗舊檔相容、鍵位與招式獨立保存、錯誤／衝突拒絕、還原與兩人輸出。正常原生雙打驗重綁方向及拳腳、兩人分離、快捷按住只觸發一次、原版斬招式路徑、設定／失焦不漏鍵、重啟保存及十一人選角。Linux 與 Windows Wine 分開記錄，macOS 編譯不稱真機驗收。GUI 截圖與確實走到的路徑才列入結果。

## 結果與限制

- `workplace/keyboard-native-v1/receipt.json` 與 `keyboard-wine-v1/receipt.json` 各六項通過：正常介面重綁、衝突／保留鍵拒絕、清空／還原、重啟保存、兩人方向與拳腳獨立輸入、兩人的斬快捷進原版 path 24h，按住只請求一次。設定前原版步數為零。
- 實際封包另由 `dist-all/v.0.1.0-20261020/smoke/linux-play-record/receipt.json` 驗預設快捷、移動、真實 X11 失焦、恢復後仍按住的鍵保持中立，直到釋放再按才生效。設定面板不漏鍵另在兩平台案例驗證。
- 舊檔相容、跨兩人鍵衝突、壞設定保留及原版輸出測試、可用 internal／cmd 套件測試及 vet 通過，見 `workplace/keyboard-release-build-v1/tests.log`。四平台各綁定 43 份實際編譯輸入。
- 斬四招的完整原版輸入證據仍以 004 為準；本次鍵盤正常路徑抽驗第一招，未宣稱所有招式重驗。其他角色僅配置保存，實際快捷拒絕。macOS、Windows 真機與實體手把未驗，不以 Wine 代替。
