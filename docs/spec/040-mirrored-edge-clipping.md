# 040：雙向翻轉的場邊裁切

狀態：CONFORMED，限定已列來源／幾何及 Linux 正常案例。修正已登錄 HD 在正常場邊投擲時的來源裁切定位；沿用 038 每格核對與整格回退，不改玩法、碰撞、原版像素、動畫或素材格式。

## 輸入與待驗根因

SF.EXE SHA 為 24b23d41c5fe6015d211b601e44b4e030677363f7232adcf9999c9ddd80d8300，SFMAN05.DAT SHA 為 b5b77d590420b92db2d265aa89483de70d58193caf442fd41eba338eb111d653。Go 1.24.13、固定 dosgolem 副本及 IDA 9.4。IDA 位址採 MZ 線性 1000h 映像，source offset 與 runtime 不混用。

正常十一人取樣的法蘭克槽 10／11 在 C0h 且右裁切 1／9 時，原貌層已完整，但 038 的幾何核對拒絕。兩種來源及保存 CPU 層見 hd-motion-coverage-v1 的 character-00／02，其他角色另有同類樣本。

原始 sub_146E8 的 14729h／1472Bh／1472Dh 在計算來源位移前將右裁切放入 BL；sub_1480A 的 14854h／14856h／14858h 則保留 BL 的左裁切。這使雙向翻轉的來源起點與只水平翻轉不同，不能將兩者合併。以上先以既有匯出定位，正式結論須回到 i64 函式及原 bytes，並重組 CPU 像素／覆蓋審查。

## 擬定呈現契約

令 L=ceil(LeftClip/2)、R=ceil(RightClip/2)、pairs=ceil(Width/2)−L−R。鏡像目的起點及可見 clip 沿既有定位；只水平翻轉的來源起點為 R，雙向翻轉為 L。雙向翻轉完整 HD 影像的 left 因此改為 destination_start+2L+1−Width，其他幾何保持。這是待審查的原版規則，不能以調位直到畫面好看取代證據。

原檔 → source hash／typed Sprite → 受驗 Placement → 同格 CPU 覆蓋／色號核對 → 既有 HD 合成；核對失敗仍整格原貌。無新增存檔或設定。READY 前不改 production Placement。

## 驗收

固定 i64 只在一次性副本查詢；四支原函式及 caller、bytes、原檔 SHA 均可回查。保存正常場邊兩類來源須逐點吻合，且舊 038／鏡像／裁切 fixture 不退步。真實素材選擇及篡改拒絕、可用測試／vet、正常原生場邊投擲的同狀態切換／恢復與繼續操作、四平台編譯輸入及標頭通過，才限定 CONFORMED。不外推所有裁切、色盤、動畫或平台實機。

## READY 審查

已證實：原 i64 的一次性副本由 IDA 9.4 重查四支 blit，每支六個直接 caller，原 bytes／operand 與舊匯出一致。14729h..1472Fh 為 8AC3／8ADF／32FF／03F3，14854h..14858h 為 8AC7／32FF／03F3；雙向翻轉保留 BL 左裁切的差異成立。資料庫原名及 bytes 未改，匯出為 edge-clip-research-v1/ida.json。

四份普通玩家來源由原檔獨立重組通過，review.json 綁定資料庫、原檔及工具 SHA。槽 10 的 2,603 寫入點、槽 11 的 2,499 寫入點全部色號／覆蓋吻合；舊共用公式分別有 2,006／3,209 個不符點。完整影像翻轉／裁切亦吻合，origin 為 (249,21)／(253,101)，clip 為 (250,21,320,104)／(262,101,320,183)。可以只修正 C0h 的來源起點，不修改其他定位或移除核對。
