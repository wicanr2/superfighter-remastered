# 046：標題與主選單 HD

狀態：DRAFT。沿 003 已確認的 B 街機手繪畫風，保留黑底紫色人物、紅金中文字標與四個按鈕的原構圖。先製作分層比較稿及核對正常標題輸出，未經技術審查及視覺確認不接正式路徑。

## 固定輸入與範圍

原版 SF.EXE、執行器與唯讀原始包身分沿 CONTEXT。TITLE.CPM SHA-256 為 `a4790f1da67dbff8eec45c573826b95ee9e9c48ed165f99dfc1cf9176ef03f10`，有界解碼得到 320×200／六位元色盤／64000 色號。解碼器在 tools/hd_source_probe.py；靜態解碼本身不等於正常顯示來源已證實。

既有正常啟動 `workplace/probe-startup-if-40m` 顯示完整標題。下方原四項為「單打、雙打、設定、結束」。人物與字標分層，按鈕文字與互動由程式呈現；不能將生成文字當成點擊命中範圍。原版規則、按鈕動作、鍵鼠及手把行為均不在本項擴充範圍。

## 蒐證與原型

- 由正常啟動鏈保存穩定標題、原按鈕回饋及離開標題的畫面；核對原輸入、索引色盤及可見顯示。
- 獨立比對 TITLE.CPM 的來源色號與實際顯示，另外定位字標、按鈕與游標；未知區域保持原貌。
- HD 人物與紅金字標採真實高解析重繪，保留原座標比例；不得用最近鄰放大代替美術。
- 比較稿及精確請求先留 workplace/title-art-v1。素材若收錄 repo，標為候選；原貌、原始色盤與收據仍留本機。比較稿不當原生完成證據。
- 正式載入／缺件回退／狀態識別與切換契約須由證據補齊並另審 READY。不得用步數、非戰鬥狀態或部分像素相似猜測目前處於標題。

垂直鏈為原檔及正常輸出 → 受驗標題身分／原按鈕狀態 → 完整 HD 構圖 → 原輸入與原流程 → 原貌切換。沒有存檔或設定變更；新素材的格式、載入方式、識別穩定性及正式視覺尚未知。背景 029 的格式決定仍獨立等待回覆，不由本原型代答。

## 正常來源核對

已證實於取樣：`workplace/title-menu-source-v2` 保存正常啟動四次，各九份未點擊標題，共 36 份；另有十五份點擊後畫面，合計 51 份。工具為 Go 1.24.13、固定 dosgolem 副本及 Pillow 11.3.0。完整畫面色號、256 色盤及 RGB 分開保存，獨立 RGB 重組全部吻合。

SFNAME.CPM SHA-256 `9268d0093b84b67508ea1e2280ec5707c20b6d31a929bfd736b89e132a1842bc`。原檔偏移 0 為 little-endian 285×94，偏移 4 flag=0，不帶色盤；偏移 5 為 FFh RLE marker，偏移 6 起解析恰為 26,790 色號。TITLE.CPM 為 320×200、flag=1、色盤偏移 5、marker 偏移 773、資料偏移 774。原始檔偏移與 runtime／IDA 位址不混用；本輪沒有新增反組譯或宣稱已定位原載入函式。

TITLE 底圖加 SFNAME 透明色號 0 疊於原座標 18／96，再加第一按鈕外框 `[27,174,81,189)`、色號 51，36 份標題逐色號完全重組相同。若將疊圖的色號 0 當不透明，完整畫面不吻合。這證實目前固定來源的顯示內容，不等同可靠的 runtime 標題識別器。

首輪已證實於取樣：原色盤 7..14 是同一八色的循環位移，只觀察 shift 3／4；其他色除 51 外均吻合 TITLE.CPM。選取框色號 51 的實際 RGB 為 251／235／170，當時其來源尚未知。下節已補足八相位及框線來源。先前驗證器假設全色盤靜態而失敗，已依原收據分清原圖、循環色與框線，不忽略差異或凍結原版動畫。

單打、雙打普通點擊後都進原選角；設定進原設定畫面，未進選角；結束回 DOS、回傳碼 0。四個點擊中心為 x=50／120／190／260、y=181。這是取樣的有效點，不能當成完整命中矩形、鍵盤導航、游標或設定全部路徑已證實。

## HD 材質換色原型與停止線

全圖僅依 RGB 換色的原型已拒絕：原色號 7 與 18 同為 RGB 207／12／12，但只有 7 輪替，不能忽略歧義或把固定下半字標一起改色。`title-animation-v1` 保留拒絕及當時工具副本。

`title_palette_preview.go --source-mask` 是可丟棄的材質假說：將原字標 7..14 的位置遮罩以雙線性投影至 HD 字標的 alpha>=16 矩形，區內使用 1..15 色差權重，區外保持原稿。這利用原位置區分動態面與固定面，但兩份畫稿的形狀不同，不能稱 HD 材質逐像素語意已證實，也不進 production。

`title-animation-v3` 保存八份配色字標、原十六步順序、框線脈動與四選項比較。所有 alpha、零相位的完整原稿及第 428 列起的固定下半字標均保持；八個相位互不相同。十六格接觸圖與四選項已目視。候選 GIF 只留本機，100 ms 是比較稿播放間隔，另有 GIF 色盤量化，不當成原版硬體時序或推廣影片。

這條原版 RE 已足以支援目前標題實作設計，不追查檔案 helper、PIT／DAC 驅動或其他非玩家阻塞。後續回到正式載入方式、材質／版面定案與正常原生驗收；只有新的玩家證據推翻以上範圍，才另開窄研究。046 仍 DRAFT，正式 API、設定、原版程式及四平台二進位保持。

## 隔離原生原型

`tools/prepare_title_native_prototype.py` 將正式來源複製到 `workplace/title-native-prototype-v1/source`，精確套用 [Core 模板](../../tools/title-native-prototype/core.go.in)及[繪圖模板](../../tools/title-native-prototype/desktop.go.in)。原型只在獨立 module 編譯，沒有改正式 `internal/`、API 或資產格式。`recipe.json` 保存 46 份正式編譯輸入、86 份副本檔案及模板雜湊；Go 1.24.13 編譯的 Linux 原型 SHA-256 為 `95f4eeb5471d714d26271576c8dedf33519d84fe89c4cf327d4dc4d7dc6ed331`。

原型在原 02CAh..0417h 生命週期內，核對完整當前原畫面、八相位、框線及游標後才顯示候選；未知或局部繪製狀態退回原貌，不重播快取畫格。候選只由 `KDZZ_TITLE_PROTOTYPE_ART` 啟用，私人目錄及固定衍生清單僅供這次比較，不是正式可攜包格式。人物填滿 960×600，字標依原 18／96 起點及 285×69 比例繪製；四個按鈕沿原表，Noto Sans CJK TC 28.8 字級經實際字面尺寸檢查。

[操作工具](../../tools/title_native_smoke.py)只送 X11 鍵鼠，從正常啟動走標題、設定往返、雙打選角及斬對法蘭克屋頂對戰。`title-native-full-v1` 保存九張擷取，前端觀測到全部八相位；這不代表八相位各有保存截圖。`title-native-fallback-v1` 未設定候選目錄，四張擷取及後續導航維持完整原貌。所有工作在限資源、無網路、UID 1000 的 Docker 內執行。

[獨立核對](../../tools/verify_title_native.py)由原 CPM、SF.EXE 表與實際色盤重建全部十份有效標題來源，並驗十三張顯示資料。暫停的 HD／原貌／恢復三張之原核心、設定、呈現及指派相同，色號與色盤完全相同，恢復 HD 的視窗像素相同；原生 HD 與原貌有 309,024 個可見像素不同。離開標題後的設定／選角保持原貌，屋頂對戰的完整原圖層另由既有重組器核對。正式 46 份編譯輸入未變。

首次原型的十三張擷取中原游標均隱藏，可見游標由下節補驗。完整換色速度、正式包缺件／損壞、Windows／macOS、實體手把與所有原標題流程仍未驗。先前 165 份原版取樣保留原範圍。材質投影與版面仍待視覺定版，正式載入契約仍待審，046 維持 DRAFT。公開原生候選截圖及來源分類見 [screenshots/source.json](../screenshots/source.json)，原貌與原始收據只留本機。

## 原游標的原生補驗

[定位探針](../../tools/title_cursor_receipt.go)從正常載入鏈啟動，只用公開 `MoveMouse`，不寫原記憶體。`workplace/title-cursor-source-v2` 在 runtime `01B9:0359`、DS `0BFAh` 保存十二份穩定畫面。中央要求 150／120，實際為 150／120；右界要求 318／100，實際為 304／100；下界要求 150／198，實際為 150／184。三組游標目的偏移分別為 38550、32304、59030，均可見。這證實固定原程式在 dosgolem 中的限界結果，不宣稱硬體滑鼠時序或越界換列是正常玩家可達狀態。

`title-native-cursor-v2` 以同一隔離二進位保存十三張，涵蓋中央、右界、下界三組 HD／原貌／恢復，以及普通滑鼠進入選角。原 CPM、SF.EXE 遮罩與當前色盤獨立重建十二份原來源及十二份有效標題擷取；GPU 上每個游標黑白像素的 3×3 顯示均相同。三組切換保持原核心／設定／指派／呈現，恢復後像素相同。滑鼠選角後標題覆繪清除，選角畫面逐點維持原貌。沒有修改原型模板、正式程式或編譯輸入。

首輪原生測試曾錯把要求座標 318 當成實際游標位置，等待超時後走到原版示範對戰；失敗保留於 `title-native-cursor-v1`，不算通過。定位探針首輪四百萬步不足四次穩定色盤邊界，`title-cursor-source-v1` 亦保留；修正只增加有界觀測預算，達四次邊界即停止。來源證據確認限界後，才以正確期望乾淨重跑原生操作。

本次三份新審查均另存 `comparison-v2.json`，原九張／四張的 `comparison.json` 與公開截圖所引用的 SHA 保持。可重播驗證命令為 `python3 tools/verify_title_native.py workplace/title-native-cursor-v2 --build workplace/title-native-prototype-v1 --cursor-source workplace/title-cursor-source-v2 --report-name comparison-v2.json`，在既有 Pillow 11.3.0 Docker 中執行。重審既有報告必須另指定檔名，不覆寫歷史報告；舊驗證器可從 Git 提交 `f37cb4e` 取出並唯讀掛載至原工具路徑。累計二十六張原生擷取只證明列明原型範圍，視覺與正式載入閘門仍待確認。
