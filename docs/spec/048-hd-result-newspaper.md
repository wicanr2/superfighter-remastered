[收錄工具](../../tools/import_result_candidates.py)逐檔複製原 bytes，另以既有斬 HD、右側鏡像法蘭克、向量重畫旗幟及字型產生[靜態比較](../screenshots/result-newspaper-candidate.png)。來源重組核對不會把原像素貼入這張公開比較。結果標題另以現代繁體中文字型排成「壓倒勝」，沒有聲稱重現原書法字形；美國旗幟以現代向量圖重畫，不宣稱原星點逐一相同。底圖細字是新印刷紋理，不能當作已辨識原新聞文字。圖上明列非遊戲擷取。

首輪已目視兩張原輸出與合成圖：法蘭克保留白髮、鬍渣與青藍衣緣，腫眼／嘴角／擦傷程度與原肖像不同；底圖框線定位與紙張紋理也為近似。該輪只補一名敗者肖像，後續十人另見下節。視覺未定版、正式格式與結果生命週期未實作，維持 DRAFT。

十張新生成原 PNG 均為 1254×1254、完全不透明，與首輪法蘭克合成[十一人純 HD 總覽](../screenshots/result-portrait-candidates.png)。每次參照左半是原受傷肖像，右半是該角色既有 HD 身分／筆觸；沒有使用別人的臉當造型依據。原對照只留本機，[逐人來源與完整提示詞](../../assets/hd/candidates/result-portraits-source.json)保存原檔偏移、原 RGB、參照面板與生成檔的雜湊。既有法蘭克原 bytes 與首輪報紙不變。

十一張已逐一目視。鳳凰與蜘蛛女保留淚痕，蜘蛛女只含頭髮／臉／頸，不作服裝或戰鬥姿態。薩爾可夫新稿兩眼皆閉，與原版單眼狀態不同；鬼丸嘴巴張幅較小；嵐臉頰浮腫被弱化；子彈的圓形頰痕及其他人的嘴角、擦傷、五官比例仍為近似。這些差異列入來源紀錄，未把檔案齊全當作視覺定版或原版完全忠實。

上述候選補稿輪沒有正常比賽的新執行，也沒有正式結果識別、載入格式、API 或畫面切換。後續目前核心的正常來源補驗見下節。三種結果分類、其他角色旗幟對照與單打結果仍依原閘門另驗，048 保持 DRAFT。

## 目前核心的正常結果生命週期

[正常結果取樣](../../tools/result_core_receipt.go)沿既有公開 Core 的雙打輸入，重新從標題選斬與法蘭克，普通移動／拳擊完成兩次擊倒、下一回合、結果等待、六次穩定取樣與 Return 返回。沒有訓練、角色／座標／生命／勝者或亂數寫入。這次實際執行目前核心，與前述只重審舊圖的工作分開。Go 1.24.13、既有 Docker 與固定原檔，總指令預算 30 億，實際結束於 1,023,750,000 步。

共十三份取樣保存在 `workplace/result-core-v1`。兩次擊倒時法蘭克為零血，下一回合恢復雙方 124；結果等待及六次穩定畫面共七份，完整 RGB 均與七份原檔重組相同，左斬 0、右受傷法蘭克 4、WC 第 0 筆、旗幟第 0／1 筆與姓名位置 42／232。兩次執行未固定亂數種子，不宣稱戰鬥過程、亂數序列或耗步逐格對拍，只核對目前正常結果狀態及來源。

[來源識別原型](../../tools/recognize_result_source.py)固定核對七份原檔 SHA，逐張辨識左右肖像、三筆結果字圖與七筆旗幟。姓名位置由實際完整字圖搜尋，不從斬／法蘭克的寬度猜其餘角色置中公式。最後以原底圖及所有找到的圖塊重組整張 64000 像素 RGB，全等才輸出來源資料。這是 DRAFT 的 tools 原型，不是正式 Core API、勝負分類或角色旗幟表。

[獨立核對](../../tools/verify_result_lifecycle.py)通過上述七份完整結果。四份對戰、第一份離戰轉場及返回標題均不被識別成結果。第一份離戰取樣的 `Battle=false` 且對戰快照清空，畫面卻仍在轉換，證實不能只靠這兩個條件顯示結果 HD。八個區域各改一個 RGB byte 及截短／加長資料全部拒絕。

Return 後完整色號由 TITLE／SFNAME 與 046 已驗的原框線程序重組，全等；選取項 1、字標色盤相位 5。未重新驗全部標題脈動時序。首輪驗證器錯把 015 已知的 192 列對戰 scanout 當成 200 列，另把命中框／一般矩形錯套到原標題框線；改用既有 015／046 契約後，同一批十三份原資料乾淨重跑通過，沒有修改產品或放寬結果全圖相等條件。

收據 SHA-256 `8f53dececcc9c6aafe80cc3d623d80da496dfcef0d9a63e7ccead853267d2410`，`source-review.json` 記錄工具與依賴雜湊。這仍是公開 Core 的無頭正常輸入證據，不取代原生視窗／GPU、單打、其他角色、其他結果、切換／恢復或正式 HD 接入。048 保持 DRAFT。

## 隔離原生結果原型

[準備／建置工具](../../tools/prepare_result_native_prototype.py)只在 `workplace/result-native-prototype-v1` 複製正式來源，套用[原生模板](../../tools/result-native-prototype/desktop.go.in)。85 份副本檔案、原 46 份編譯輸入與來源雜湊均綁定 recipe。Go 1.24.13 的 Linux 二進位 SHA-256 `73a49e3fa9accdf087548a39fc2b87eef52f57dc3085101f2ca8f76bf0ae1c62`；未移入正式 bin 或封包。

原型對每張完整結果核對七份原檔，左右肖像／結果字圖／旗幟／姓名由全部原 RGB 逐點辨識，再重組整張 64000 像素。只有完整相同才畫候選，Go 輸出另由前節 Python 原型獨立核對。原參照約 1.18 MB，只在本機，不當作正式資產格式或公開來源包。

`KDZZ_RESULT_PROTOTYPE_REFERENCE` 指向本機固定 recipe；`KDZZ_RESULT_PROTOTYPE_ART` 才啟用候選。23 張已保存原 PNG 及兩張由純 HD 靜態比較裁出的向量旗幟合計 25 項，全組核對後才建立獨立紋理。只有旗幟來源第 0／1 筆有 HD，其餘五筆安全保留原貌。三種結果標題在原型使用現代字型重排，不據此宣稱三種正常結果或分類門檻已驗；字形、姓名與整體視覺尚未定版。

[原生操作](../../tools/result_native_smoke.py)只用 X11 普通鍵鼠，從正常標題選斬／法蘭克，兩回合各實際把對手血量打至零，再到結果及 Return 返回。`result-native-full-v2` 與 `result-native-fallback-v2` 各十張，後者未載任何候選，結果整張保持原貌。首版 v1 操作沿舊腳本把第二回合開場的非零 round_state 誤標回合結束，造成未攻擊等待及假 time-expiry 標籤；確認原因後主動停止並保留部分收據。修正只以實際零血判 KO，兩個 v2 都嚴格要求兩次 KO，沒有改產品、生命或原判勝。

[獨立核對](../../tools/verify_result_native.py)通過二十張原生擷取、六份完整原結果重組、兩份 GPU 候選身分／右側鏡像辨識。暫停下切換原貌／恢復保持核心、呈現、設定與指派，兩組恢復的視區像素相同；原貌與未載候選都逐點等於原結果。Return 後清除候選，整個視區回到即時原標題。Pillow 只用作候選身分比對，不宣稱 GPU 採樣逐點一致。

[公開截圖](../screenshots/result-native-prototype-hd.png)確為正常比賽後的隔離原生視窗，視區由不透明新底圖、HD 肖像、向量旗幟及專案字型完整覆蓋，不含原貌比較。原圖、原色盤與原參照 JSON 仍只留本機。這是 Linux 一組雙打原型，不取代單打、其他角色／結果／旗幟、Windows／macOS、損壞素材或正式包驗收。048 保持 DRAFT。
