## 目前核心的正常結果生命週期

[正常結果取樣](../../tools/result_core_receipt.go)沿既有公開 Core 的雙打輸入，重新從標題選斬與法蘭克，普通移動／拳擊完成兩次擊倒、下一回合、結果等待、六次穩定取樣與 Return 返回。沒有訓練、角色／座標／生命／勝者或亂數寫入。這次實際執行目前核心，與前述只重審舊圖的工作分開。Go 1.24.13、既有 Docker 與固定原檔，總指令預算 30 億，實際結束於 1,023,750,000 步。

共十三份取樣保存在 `workplace/result-core-v1`。兩次擊倒時法蘭克為零血，下一回合恢復雙方 124；結果等待及六次穩定畫面共七份，完整 RGB 均與七份原檔重組相同，左斬 0、右受傷法蘭克 4、WC 第 0 筆、旗幟第 0／1 筆與姓名位置 42／232。兩次執行未固定亂數種子，不宣稱戰鬥過程、亂數序列或耗步逐格對拍，只核對目前正常結果狀態及來源。

[來源識別原型](../../tools/recognize_result_source.py)固定核對七份原檔 SHA，逐張辨識左右肖像、三筆結果字圖與七筆旗幟。姓名位置由實際完整字圖搜尋，不從斬／法蘭克的寬度猜其餘角色置中公式。最後以原底圖及所有找到的圖塊重組整張 64000 像素 RGB，全等才輸出來源資料。這是 DRAFT 的 tools 原型，不是正式 Core API、勝負分類或角色旗幟表。

[獨立核對](../../tools/verify_result_lifecycle.py)通過上述七份完整結果。四份對戰、第一份離戰轉場及返回標題均不被識別成結果。第一份離戰取樣的 `Battle=false` 且對戰快照清空，畫面卻仍在轉換，證實不能只靠這兩個條件顯示結果 HD。八個區域各改一個 RGB byte 及截短／加長資料全部拒絕。
